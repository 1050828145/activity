# 活动参与人员清单导出筛选功能说明

## 更新概述

为数据产品中的"活动和参与人员清单"导出功能添加筛选支持，用户可以指定参与状态和发薪状态，只导出符合条件的参与人员，提升导出的灵活性和实用性。

## 一、功能说明

### 1.1 筛选功能定义

**筛选导出**：在导出配置对话框中设置筛选条件，只导出符合条件的参与人员数据。

**筛选条件**：
1. **参与状态**：待确认、已确认、已出席、已合格、未出席、已取消
2. **发薪状态**：全部、已发薪、未发薪

**筛选规则**：
- 可以不选择任何筛选条件（导出全部）
- 参与状态支持多选
- 发薪状态单选
- 多个筛选条件采用逻辑与（AND）关系

### 1.2 实现效果

#### 示例1：导出已出席的参与人员
```
筛选条件：
- 参与状态：已出席
- 发薪状态：全部

结果：只导出参与状态为"已出席"的人员
```

#### 示例2：导出已出席且未发薪的参与人员
```
筛选条件：
- 参与状态：已出席
- 发薪状态：未发薪

结果：只导出参与状态为"已出席"且未发薪的人员
```

#### 示例3：导出已确认或已出席的参与人员
```
筛选条件：
- 参与状态：已确认、已出席
- 发薪状态：全部

结果：导出参与状态为"已确认"或"已出席"的人员
```

### 1.3 使用场景

| 场景 | 筛选条件 | 用途 |
|------|---------|------|
| 发薪名单 | 已出席 + 未发薪 | 生成待发薪人员名单 |
| 出勤统计 | 已出席 + 已合格 | 统计实际出勤人员 |
| 确认名单 | 已确认 | 查看已确认参与的人员 |
| 缺席统计 | 未出席 | 统计缺席人员 |
| 取消统计 | 已取消 | 查看取消参与的人员 |
| 合格名单 | 已合格 + 已发薪 | 查看已完成发薪的合格人员 |

## 二、筛选条件详解

### 2.1 参与状态筛选

**可选状态**：
1. **待确认**：报名但未确认参与
2. **已确认**：确认参与但未出席
3. **已出席**：已出席活动
4. **已合格**：已出席且通过评估
5. **未出席**：确认参与但未出席
6. **已取消**：取消参与

**选择方式**：
- 点击状态标签进行选择/取消选择
- 支持多选
- 选中状态显示为蓝色背景
- 未选中状态显示为灰色背景

**筛选逻辑**：
```typescript
// 参与状态筛选（多选，逻辑或关系）
if (filterStatus.length > 0) {
  participants = participants.filter(p => filterStatus.includes(p.status));
}
```

**说明**：
- 如果选择多个状态，导出符合任一状态的人员
- 如果不选择任何状态，导出所有状态的人员

### 2.2 发薪状态筛选

**可选状态**：
1. **全部**：不筛选发薪状态
2. **已发薪**：已发放工资
3. **未发薪**：未发放工资

**选择方式**：
- 点击状态标签进行选择
- 单选，只能选择一个
- 选中状态显示为蓝色背景
- 未选中状态显示为灰色背景

**筛选逻辑**：
```typescript
// 发薪状态筛选
if (filterIsPaid !== 'all') {
  const isPaidValue = filterIsPaid === 'true';
  participants = participants.filter(p => p.is_paid === isPaidValue);
}
```

**说明**：
- 默认选择"全部"，导出所有发薪状态的人员
- 选择"已发薪"，只导出已发薪的人员
- 选择"未发薪"，只导出未发薪的人员

### 2.3 组合筛选

**筛选顺序**：
1. 先应用参与状态筛选
2. 再应用发薪状态筛选

**组合示例**：

#### 示例1：已出席 + 未发薪
```
筛选条件：
- 参与状态：已出席
- 发薪状态：未发薪

筛选逻辑：
1. 筛选出参与状态为"已出席"的人员
2. 在结果中筛选出未发薪的人员

结果：已出席且未发薪的人员
```

#### 示例2：已确认或已出席 + 已发薪
```
筛选条件：
- 参与状态：已确认、已出席
- 发薪状态：已发薪

筛选逻辑：
1. 筛选出参与状态为"已确认"或"已出席"的人员
2. 在结果中筛选出已发薪的人员

结果：(已确认或已出席) 且已发薪的人员
```

#### 示例3：不选择任何筛选条件
```
筛选条件：
- 参与状态：不选择
- 发薪状态：全部

结果：导出所有参与人员
```

**说明**：
- `filterStatus`：参与状态数组，支持多选
- `filterIsPaid`：发薪状态字符串，单选

### 4.2 状态切换函数

```typescript
// 切换参与状态
const toggleStatus = (status: string) => {
  if (filterStatus.includes(status)) {
    setFilterStatus(filterStatus.filter(s => s !== status));
  } else {
    setFilterStatus([...filterStatus, status]);
  }
};

// 设置发薪状态
setFilterIsPaid(value); // 直接设置
```

**说明**：
- `toggleStatus`：切换参与状态的选中/未选中
- `setFilterIsPaid`：直接设置发薪状态

## 七、常见问题

### Q1: 为什么要添加筛选功能？
**A**: 
- 提高导出的灵活性
- 减少手动筛选工作量
- 满足不同场景的导出需求
- 提升数据处理效率

### Q2: 筛选条件是必选的吗？
**A**: 
- 不是必选的
- 可以不选择任何筛选条件
- 不选择时导出所有参与人员

### Q3: 参与状态可以多选吗？
**A**: 
- 可以多选
- 选择多个状态时，导出符合任一状态的人员
- 使用逻辑或（OR）关系

### Q4: 发薪状态可以多选吗？
**A**: 
- 不可以多选
- 只能选择一个状态
- 默认选择"全部"

### Q5: 筛选条件如何组合？
**A**: 
- 参与状态和发薪状态采用逻辑与（AND）关系
- 先应用参与状态筛选，再应用发薪状态筛选
- 例如：已出席 + 未发薪 = 已出席且未发薪的人员

### Q6: 如果筛选后没有数据怎么办？
**A**: 
- Excel中会显示提示信息
- 提示信息："暂无符合条件的参与人员"
- 不会生成空的Excel文件

### Q7: 筛选条件会影响导出字段吗？
**A**: 
- 不会影响
- 筛选条件只影响导出的数据行
- 导出字段配置独立于筛选条件

### Q8: 可以保存筛选条件吗？
**A**: 
- 当前版本不支持
- 每次打开对话框需要重新设置
- 未来可以考虑添加保存功能

### Q9: 筛选条件会影响所有活动吗？
**A**: 
- 会影响所有选中的活动
- 每个活动都应用相同的筛选条件
- 如果需要不同筛选条件，需要分批导出

### Q10: 如何导出全部参与人员？
**A**: 
- 不选择任何参与状态
- 发薪状态选择"全部"
- 或者直接点击"确认导出"
