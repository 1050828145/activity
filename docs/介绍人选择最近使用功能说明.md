# 介绍人选择最近使用功能说明

## 更新概述

为介绍人（领队）选择对话框添加"最近使用"功能，在领队列表最前面显示最近使用过的领队，方便用户快速选择常用的介绍人，提高操作效率。

## 一、功能说明

### 1.1 最近使用定义

**最近使用**：记录用户最近选择过的领队，并在领队列表最前面显示，方便快速选择。

**记录规则**：
- 每次选择领队时，自动记录到最近使用列表
- 最多保存5个最近使用的领队
- 按使用时间倒序排列（最近使用的在最前面）
- 如果重复选择同一个领队，会更新其位置到最前面

**存储方式**：
- 使用localStorage存储
- 存储键名：`recent_leaders`
- 存储内容：领队ID数组
- 持久化存储，刷新页面不丢失

### 1.2 实现效果

#### 领队列表布局
```
选择介绍人(领队)
├── 搜索框
├── 当前选择（如果有）
└── 领队列表
    ├── 最近使用（如果有）
    │   ├── 领队1
    │   ├── 领队2
    │   └── ...
    └── 全部领队
        ├── 领队A
        ├── 领队B
        └── ...
```

#### 分组显示
- **最近使用**：显示最近使用过的领队（最多5个）
  - 标题：最近使用
  - 图标：时钟图标（Clock）
  - 背景：浅灰色背景（bg-muted/80）
  - 位置：列表最前面

- **全部领队**：显示所有其他领队
  - 标题：全部领队
  - 背景：浅灰色背景（bg-muted/80）
  - 位置：最近使用之后

#### 搜索时的显示
- 搜索时不显示分组
- 直接显示搜索结果
- 搜索结果包含所有匹配的领队（包括最近使用的）

## 二、功能详解

### 2.1 最近使用记录

**触发时机**：
- 用户在领队选择对话框中点击某个领队时
- 自动记录该领队到最近使用列表

**记录逻辑**：
```typescript
1. 获取当前的最近使用列表
2. 移除列表中已存在的相同领队ID（如果有）
3. 将新选择的领队ID添加到列表开头
4. 限制列表长度为5个
5. 保存到localStorage
```

**示例**：
```
初始状态：[]
选择领队A：[A]
选择领队B：[B, A]
选择领队C：[C, B, A]
再次选择领队A：[A, C, B]（A移到最前面）
```

### 2.2 最近使用显示

**显示条件**：
- 有最近使用的领队记录
- 没有进行搜索（searchQuery为空）

**显示内容**：
- 标题：最近使用
- 图标：时钟图标（Clock）
- 领队列表：按最近使用时间倒序排列

**样式设计**：
- 标题背景：bg-muted/80（浅灰色半透明）
- 标题样式：text-sm font-medium text-muted-foreground
- 图标：h-4 w-4
- 边框：border-b border-border

### 2.3 全部领队显示

**显示条件**：
- 有其他领队（不在最近使用中的）
- 没有进行搜索（searchQuery为空）

**显示内容**：
- 标题：全部领队
- 领队列表：按数据库查询顺序排列

**样式设计**：
- 标题背景：bg-muted/80（浅灰色半透明）
- 标题样式：text-sm font-medium text-muted-foreground
- 边框：border-b border-border

### 2.4 搜索结果显示

**显示条件**：
- 用户输入了搜索关键词（searchQuery不为空）

**显示内容**：
- 不显示分组标题
- 直接显示所有匹配的领队
- 搜索结果包含最近使用和全部领队

**搜索逻辑**：
- 搜索领队姓名、联系方式、微信
- 不区分大小写
- 模糊匹配

```typescript
const recentLeaders = useMemo(() => {
  const recentIds = getRecentLeaderIds();
  return leaders.filter(leader => recentIds.includes(leader.id))
    .sort((a, b) => {
      const indexA = recentIds.indexOf(a.id);
      const indexB = recentIds.indexOf(b.id);
      return indexA - indexB;
    });
}, [leaders]);
```

**说明**：
- 使用`useMemo`缓存计算结果
- 根据最近使用的ID列表筛选领队
- 按ID在列表中的顺序排序

const otherLeaders = useMemo(() => {

## 六、数据管理

### 6.1 存储机制

**存储位置**：localStorage

**存储键名**：`recent_leaders`

**存储内容**：
```json
["leader-id-1", "leader-id-2", "leader-id-3", "leader-id-4", "leader-id-5"]
```

**存储格式**：JSON字符串

**存储时机**：
- 每次选择领队时自动保存
- 实时更新

### 6.2 数据限制

**最大数量**：5个

**超出处理**：
- 保留最近的5个
- 删除最早的记录

**重复处理**：
- 如果重复选择同一个领队
- 移除旧记录
- 添加到最前面

### 6.3 数据清理

**自动清理**：
- 不会自动清理
- 持久化存储

**手动清理**：
- 可以调用`clearRecentLeaders()`函数清理
- 清除浏览器缓存会清理

**数据迁移**：
- 如果领队被删除，最近使用列表中的ID会失效
- 失效的ID不会显示在列表中
- 不会影响其他有效的记录
